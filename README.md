# Infra Systems

Live site: https://xio-shark.github.io/infra-systems/

A static course site for three courses:

- **INFRA 01 · Distributed Systems** — 21 lectures + project demos, 5 Go labs, based on the MIT 6.5840 schedule.
- **INFRA 02 · Cloud-Native Systems** — 14 lectures, 5 Linux labs on containers, images, networking, and multi-container systems.
- **INFRA 03 · Agent OS** — 12 lectures, 5 labs and a capstone on kernel-level atomic operations for agents. This is exploratory material, not a mainstream consensus.

The site is generated with Pandoc from `content/*.md` and served as plain HTML. It has no backend and no build-time JavaScript framework. A handful of mechanism animations are plain SVG/DOM, loaded from `assets/anim.js`.

## Build

```bash
./build.sh
```

Output is in `dist/`. Open `dist/index.html` or serve it locally:

```bash
python3 -m http.server 8000 -d dist
```

## Animations

Hard mechanisms have step-through animations: MapReduce, RPC retries, GFS writes, Paxos, Raft election, log replication, Figure 8, snapshots, linearizability, 2PC, shard migration, container namespaces, Service VIPs, workspace transactions, and leases/fencing. They are ordinary `<div class="anim" data-anim="...">` placeholders in the Markdown; `assets/anim.js` renders the scene and controls.

- No external library, no network requests, no autoplay.
- `prefers-reduced-motion` removes transitions but keeps step navigation.
- Without JavaScript the fallback paragraph remains; the surrounding text is still complete.

To add a scene, register it in `assets/anim.js` under `InfraAnim.SPECS` and put the placeholder in the page. `build.sh` includes `anim.css` and `anim.js` in the asset hash.

## Local judge

`judge/` runs behavioral tests and reports a score. It does not contain solutions.

```bash
./judge/run.sh --list
LAB_ROOT=~/labs/6.5840 ./judge/run.sh infra01 lab1
SUBMISSION=~/labs/cn1/cn1 CN1_ROOTFS=~/labs/cn1-rootfs ./judge/run.sh infra02 cn1
```

`--quick` is a smoke test and never reports a full pass. `--json` keeps a meaningful exit code: 0 only when every selected lab is PASS.

See `judge/README.md` for contracts and how to add a lab.

## GitHub Pages

The repository includes `.github/workflows/pages.yml`, which builds the site with Pandoc and deploys `dist/` to GitHub Pages.

1. Create a repository (public, unless your plan supports Pages from private repos).
2. Push this directory as the repository root.
3. In **Settings → Pages**, set **Source** to **GitHub Actions**.
4. Push to `main` or run the workflow manually.

The site uses relative links, so it works under `https://<user>.github.io/<repo>/` without a custom domain. `dist/.nojekyll` is generated by `build.sh`.

The template currently sets `noindex, nofollow`. If you want the course to be searchable, remove that meta tag from `template.html`.

## Caching

GitHub Pages serves every file with `cache-control: max-age=600` and does not support custom response headers. `build.sh` therefore appends a content hash to the stylesheet, script, and font URLs (`assets/style.css?v=<hash>`, `dist/version.json`), so a rebuild invalidates exactly the files that changed. `assets/app.js` compares its baked-in hash with `version.json` on load and reloads once with the new `?v=` after a deploy. The HTML document itself can still be up to 10 minutes stale; a hard reload or a fresh `?v=` in the page URL bypasses that.


## Constraints

- All core labs run on one Linux or WSL2 machine: 2 vCPU, 4 GB RAM, 20 GB disk. No GPU, KVM, or multi-node cluster.
- The site does not include lab code or answers.
- INFRA 01 follows the MIT 6.5840 collaboration policy; its lecture notes are original Chinese summaries, not translations.
- INFRA 02/03 are original course material; readings are linked to public papers, specs, and documentation.
- INFRA 03 is explicitly exploratory: it proposes hypotheses and asks readers to argue for or against them, rather than presenting a standard.
